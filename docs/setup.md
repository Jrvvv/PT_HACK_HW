# Развёртывание стенда для перебора

Этот стенд нужен для способа 1 (`docs/hardware-bruteforce.md`) — автоматического подбора пароля через эмуляцию энкодера. Для способа 2 отдельного стенда не требуется, достаточно дампа флеш-памяти и `tools/pin_model.py`.

## Что понадобится

- Компьютер с Linux и Python 3.11 или новее.
- Плата ESP32 с прошитым MicroPython, подключённая к компьютеру по USB (обычно определяется как `/dev/ttyUSB0` или похожее устройство).
- Сама плата CyberSafe с подключённым к ней энкодером и индикаторами.
- По желанию — веб-камера, направленная на статусную лампу устройства: без неё стенд работает, но не умеет отличать успешный ввод от неудачного по цвету лампы.

## Установка зависимостей на хосте

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
chmod +x host/start_bridge.sh
```

## Прошивка ESP32

Прошивка эмулятора энкодера копируется на плату один раз через `mpremote`:

```bash
mpremote connect /dev/ttyUSB0 cp esp/encoder.py :encoder.py
mpremote connect /dev/ttyUSB0 cp esp/main.py :main.py
mpremote connect /dev/ttyUSB0 reset
```

Порт устройства нужно подставить свой — посмотреть его можно командой `ls /dev/ttyUSB* /dev/ttyACM*`.

## Распиновка

ESP32 подключается к линиям энкодера платы CyberSafe:

| Сигнал | Вывод ESP32 |
|---|---|
| Энкодер, канал A | GPIO21 |
| Энкодер, канал B | GPIO23 |
| Кнопка подтверждения | GPIO19 |
| Общий провод | GND |

Индикаторные светодиоды платы (показывают, сколько цифр пароля уже набрано) заведены обратно на входы ESP32, чтобы хост мог отслеживать прогресс ввода:

| Позиция цифры | Вывод платы CyberSafe | Вывод ESP32 |
|---|---|---|
| 1-я | GP13 | GPIO22 |
| 2-я | GP12 | GPIO5 |
| 3-я | GP11 | GPIO18 |
| 4-я | GP10 | GPIO17 |

Полная карта соединений сохранена в `board_map.json`. Стоит иметь в виду, что GPIO5 на ESP32 — один из выводов, определяющих режим загрузки платы, поэтому подтяжку на нём менять не нужно.

## Запуск

```bash
./host/start_bridge.sh
```

После запуска в терминале появится адрес открытого USB-порта и адрес веб-интерфейса. По умолчанию интерфейс доступен на `http://127.0.0.1:8080/` и состоит из нескольких страниц:

| Страница | Назначение |
|---|---|
| `/` | Ручное управление энкодером из браузера |
| `/probe.html` | Показания четырёх индикаторных светодиодов в реальном времени |
| `/bruteforce.html` | Запуск автоматического перебора, остановка, текущий цвет статусной лампы |
| `/map.html` | Карта уже перебранных кодов, раскрашенная по результату |

## Запуск перебора

Перебор запускается через веб-интерфейс `/bruteforce.html` либо напрямую через API:

```bash
curl -s -X POST http://127.0.0.1:8080/api/bruteforce/start \
  -H 'Content-Type: application/json' \
  -d '{"delay":0.001,"start":0,"end":9999}'
```

Остановка:

```bash
curl -s -X POST http://127.0.0.1:8080/api/bruteforce/stop -H 'Content-Type: application/json' -d '{}'
```

Ввод конкретного кода вручную, без перебора:

```bash
curl -s -X POST http://127.0.0.1:8080/api/code \
  -H 'Content-Type: application/json' \
  -d '{"code":"3736","delay":1.0}'
```

Текущее состояние стенда, включая показания индикаторов и статус перебора, доступно через `GET /api/state` и `GET /api/bruteforce/status`.

## На что обратить внимание

Индикаторы прогресса на плате показывают только количество принятых цифр, а не совпадение с паролем, поэтому по ним одним нельзя определить успех попытки — за это отвечает камера и цвет статусной лампы, подробности в `docs/hardware-bruteforce.md`. Если камера не подключена, стенд продолжает работать и перебирать коды, но не сможет автоматически определить, какой из них подошёл — тогда правильный код нужно будет определять по факту появления накопителя `PositiveLabs Flash MSC` в системе (`lsusb | grep -i Positive`, идентификатор `cafe:4000`).

Если после ввода очередного кода индикация зависает и не возвращается в исходное состояние, стенд сам отправляет на плату несколько «холостых» сигналов и нажатий, чтобы сбросить незавершённый ввод, а затем повторяет попытку.
